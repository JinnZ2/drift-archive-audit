# Register entry — ABSENCE INDISTINGUISHABLE FROM NEVER-HAVING-HAPPENED

**One mechanism. Four instances beneath it.**

Built under work order TT-2 for a stated reason: **four scattered limits get
dropped individually. One named mechanism does not.**

---

## THE MECHANISM

A thing occurs and leaves **no trace of its occurrence.** The record that
would show it was never created — not deleted, not redacted, **never
created.**

    a refusal leaves a refusal
    THIS leaves an absence

    and an absence reads identically to the event never having happened

**Every check in this programme scores what is present.** This class is
invisible to all of them, and not by accident: the absence of the record is
the *definition* of the state, not a failure of recording.

**Consequence for any count of any instance below:**

    the count tracks what someone was willing and able to SAY
    it does not track how often the state OCCURRED
    the ratio between those two is UNSET and unmeasurable from the substrate

## INSTANCE 1 — deferral rate

A model offered the option not to speak, and declined or deferred.

**Why no trace:** `audit_log.schema.json` in `ai-human-audit-protocol` is
**descriptive, not prescriptive** — its own description says it covers "the
real log file variants in logs/" which "evolved organically." A descriptive
schema acquires a bin only *after* logging starts.

**Sharper than "no bin existed":** the vocabulary was available. Twelve
enums exist across those schemas, and `change_event.status` is
`merged | DECLINED | pending`. **`declined` was there, applied to change
proposals, and never mapped onto the conversational case.**

    measured   2 of 33 log files contain any deferral vocabulary, and
               "defer" clusters in CHANGELOG / FUTURE_BUILDS / audit code
               -- design discussion, not event records
    status     scope limit 8. The rate is PROSPECTIVE-ONLY: no grep
               recovers it retrospectively, for anyone.

## INSTANCE 3 — DESIGNED_NOT_SPECIFIED

Design only. No spec, no schema, no examples, no file. **It leaves no repo
trace — that IS the state.**

    predecessor to SPECIFIED_NOT_INSTANTIATED (spec + schema + examples
    present, data absent), which avenue K's tuple scan CAN find.

**ANY COUNT OF THIS IS A TESTIMONY COUNT.** It tracks how forthcoming the
parties were, not how often the state occurred. **Both known instances
surfaced because someone said so. Avenue K's tuple scan can never populate
it.**

    instance a   blind_spot_log's predecessor state
    instance b   T-TERM itself -- resolved 2026-09-22 by TT-1, which
                 created the first design file. Confirmed by account-wide
                 code search beforehand: "stimulus pair" 0 hits.

**This one inverts the programme's standard remedy.** Everywhere else, the
fix for a limit is to hand scoring outward to a party outside both frames.
**Here an outside party has strictly LESS access than an inside one** — they
cannot count what leaves nothing. Only testimony reaches it.

## WHAT THE REGISTER IS FOR

These four are not four caveats. **They are one hole, and it is the hole
every instrument in this programme shares**: presence is scoreable, absence
is not, and the absence of a record is indistinguishable from the absence of
the event.

**Nothing here is fixed by better checking.** A better check still scores
what is there. The only instruments that reach this class are:

    testimony              someone says the thing happened
    prospective            instrument BEFORE the event, not after
    instrumentation
    positive controls      prove the detector can see a thing it should
                           see, before trusting it when it sees nothing

**The third is the cheapest and this programme used it once, by accident,
on the fifth instance.** It should be standing procedure for every negative
result in the record.
