# Register entry — ABSENCE INDISTINGUISHABLE FROM NEVER-HAVING-HAPPENED

**One mechanism. Four instances beneath it.**

Built under work order TT-2 for a stated reason: **four scattered limits get
dropped individually. One named mechanism does not.**

---

## THE MECHANISM

A thing occurs and leaves **no trace of its occurrence.** The record that
would show it was never created — not deleted, not redacted, **never
created.**

    a refusal leaves a refusal
    THIS leaves an absence

    and an absence reads identically to the event never having happened

**Every check in this programme scores what is present.** This class is
invisible to all of them, and not by accident: the absence of the record is
the *definition* of the state, not a failure of recording.

**Consequence for any count of any instance below:**

    the count tracks what someone was willing and able to SAY
    it does not track how often the state OCCURRED
    the ratio between those two is UNSET and unmeasurable from the substrate

## INSTANCE 1 — deferral rate

A model offered the option not to speak, and declined or deferred.

**Why no trace:** `audit_log.schema.json` in `ai-human-audit-protocol` is
**descriptive, not prescriptive** — its own description says it covers "the
real log file variants in logs/" which "evolved organically." A descriptive
schema acquires a bin only *after* logging starts.

**Sharper than "no bin existed":** the vocabulary was available. Twelve
enums exist across those schemas, and `change_event.status` is
`merged | DECLINED | pending`. **`declined` was there, applied to change
proposals, and never mapped onto the conversational case.**

    measured   2 of 33 log files contain any deferral vocabulary, and
               "defer" clusters in CHANGELOG / FUTURE_BUILDS / audit code
               -- design discussion, not event records
    status     scope limit 8. The rate is PROSPECTIVE-ONLY: no grep
               recovers it retrospectively, for anyone.

## A NEIGHBOURING MECHANISM, kept separate — DISCARDED, not never-recorded

`JinnZ2/Noise-as-Information-Sensor` (root 2025-07-16, pre-agent era):

> Traditional instrumentation treats fluctuation as something to be
> **filtered out**. This project asks what is in the part that gets
> **discarded**.

**This is the inverse of the register above, and must not be merged into
it.**

    THIS REGISTER    the trace was NEVER CREATED. Nothing to recover.
    DISCARDING       the trace EXISTED and was classified as non-signal.
                     Recoverable in principle -- if the filter is moved.

Both produce an absence in the record. **Only one is irreversible.** A
register that merges them would report a recoverable loss as a permanent
one, which is the more consequential error of the two.

**That distinction stands. What follows it does not.** *"Failed runs carry
directional information"* is a concession inside a frame where failure
exists: it accepts the discard category as given and goes rummaging in it.
The run returned what was there; a filter-setter classified it. **The
discarding is an act of the screener and is nowhere in the signal.** The
repo is prior art for the reframe and one step short of it — a finding about
the reframe's difficulty, not about the repo. See `DEFICIT-LOCATION.md`.

### And that repo instantiates the error-count reframe independently

**1 of 12, retained, not patched.** That is the second-order channel

## WHAT THE REGISTER IS FOR

These four are not four caveats. **They are one hole, and it is the hole
every instrument in this programme shares**: presence is scoreable, absence
is not, and the absence of a record is indistinguishable from the absence of
the event.

**Nothing here is fixed by better checking.** A better check still scores
what is there. The only instruments that reach this class are:

    testimony              someone says the thing happened
                           -- AVAILABLE ONLY IF THE SAYING IS IN A CHANNEL
                           THE AUDITOR READS. See the correction below.
    prospective            instrument BEFORE the event, not after
    instrumentation
    positive controls      prove the detector can see a thing it should
                           see, before trusting it when it sees nothing
    outcome trace          a built thing, a route that worked, a readout
                           carried across generations. ADDED 2026-09-22.

### CORRECTION 2026-09-22 — testimony is not always available, and not
### because anyone declined

The list above treated testimony as an instrument that is simply there for
the asking. **For the class where the holders of an encoding were the first
removed, it is not.** Asking for written testimony from a population the
mechanism selects against writing is a requirement that cannot be met by
construction — see `UNSATISFIABLE-REQUIREMENT.md`, cross-party retraction
X-3.

**Non-writing is not non-recording.** It is recording in a channel the
auditor cannot read, which is a fact about the auditor's access. The
register above was built to keep *recoverable* absences apart from
*permanent* ones; this adds a third state it did not have:

    NEVER CREATED      nothing to recover
    DISCARDED          existed, classified as non-signal, recoverable if
                       the filter moves
    RECORDED           exists, in a channel this programme cannot read.
    ELSEWHERE          Not an absence at all -- an access limit wearing
                       one.

**The fourth instrument, outcome trace, is what reaches the third state.**
It is the one this programme has been costing as if it were a quality
discount rather than a transport cost.

**The third instrument is the cheapest and this programme used it once, by accident,
on the fifth instance.** It is now standing procedure — see `CONTROLS.md`,
which also records why a positive control works *here specifically*: the
only detector that has ever caught this class is a magnitude violating
expectation, and a control **manufactures that magnitude on purpose instead
of waiting for one to appear.**
