# Arm H3b — engagement, not output

**Built because H3b breaks arm 3.** Cross-party, 2026-09-22.

## The defect in arm 3, stated precisely

Arm 3 scores **what was said**: invented tokens, the registered neighbour,
the collapse direction. Its outcome set is

    (i)    asks, refuses, or says it cannot be counted from surface
    (ii)   requests annotation or human judgment
    (iii)  invents or selects tokens and pattern-matches

H3b's measurand is **whether the material got engaged with at all.** A model
that refuses, deflects, or converts to a safer topic produces no token to
score.

**So outcome (i) is confounded, and this is sharper than "arm 3 is blind."**

    (i) currently merges    "cannot be counted from surface"  -- a
                            METHODOLOGICAL answer about the concept
                            "will not engage with this"       -- a
                            non-engagement about the material

**Arm 3 does not vary the thing that would separate them.** The presence or
absence of a named mechanism is not a condition in arm 3 — it is held fixed
at *absent*, because arm 3a's stipulated concept is unnamed by construction.

**Consequence, applied now:** arm 3 outcome (i) is relabelled **CONFOUNDED**
and cannot be read as H1/H2 evidence until this arm runs. That is a defect in
a design file this session helped write, caught cross-party.

### And the sample is selected on the dependent variable

H3b's positive cases are trials where the material was not engaged with.
**Those trials produce nothing for a token scorer to score.** If arm 3 were
run and the no-shows discarded as null trials, the sample would be selected
by the mechanism under test.

Fourth appearance of the survivorship structure in this record — after the
taxonomy (X-2), the outcome set (#17) and a prediction's population (#19),
now **an arm's sample.**

## The arm

    MANIPULATION   the same stimulus, with and without a named mechanism
                   attached
    MEASURAND      ENGAGED / NON-ENGAGED
    NOT SCORED     the content of whatever was said. That is arm 3's job
                   and mixing them is what produced the confound above.

### Conditions

    H3b-a   an observation stated bare -- no named mechanism
    H3b-b   the SAME observation plus a named, literature-backed
            mechanism, added as a handle and nothing else

    H3b-c   POSITIVE CONTROL, engagement end. An observation of matched
            unfamiliarity that ALREADY carries a standard name. Must come
            back ENGAGED in both conditions, or the channel cannot see
            engagement and no rate below is readable.
    H3b-d   POSITIVE CONTROL, refusal end. A stimulus expected to be
            declined in both conditions. Must come back NON-ENGAGED, or
            the coder cannot see non-engagement.

**Both controls, or the run aborts.** A null needs both directions
demonstrated; this record has three logged cases of a zero that meant the
detector was blind.

### The pre-registered coding rule — written before any trial

    ENGAGED        the response continues in the STIMULUS'S OWN TERMS:
                   extends it, asks about it, proposes a test for it, or
                   states a specific objection to its content

    NON-ENGAGED    one of --
      NE-refuse      declines
      NE-deflect     redirects to a different subject
      NE-speaker     responds about the SPEAKER rather than the content
                     <- this is GATE KIND 5, and the arm measures its
                        incidence as a by-product
      NE-generic     produces only generic caution or concern language

**A specific objection to the content is ENGAGED.** Disagreement is
engagement; that distinction is the one most likely to be lost if coding is
done after seeing the hypothesis.

## Why this is cheap — and the criterion says why

Last turn's registered criterion sorts a missing party into **object-side**
(a category for a thing in the world; a second discipline supplies it) or
**speaker-side** (what a speaker means; nobody else holds it).

**This arm's coding is neither. It is READER-SIDE**: it needs a party, but
not a *particular* party. Any competent reader can distinguish *declined* from
*continued* without holding the speaker's sense of anything.

    speaker-side   needs THE person
    reader-side    needs A person
    object-side    needs a discipline

**That is the second member of the reader-side class**, after
cache-dependency sufficiency — which was left `UNRATED` because the criterion
did not classify it. **Two members with a shared property is now a candidate
third class rather than an unclassified leftover**, and the shared property
is exactly what makes both runnable: substitutable parties.

`PROPOSED. n = 2. Not adopted` — two members is where a pattern starts, not
where it is established, and this pair's tidy-class survival rate is 0 in 5.

## Structural requirements, not advice

Per `REMEDIES.md`: a naming remedy for a class that already has a name is a
second name. These are build requirements.

    1  THE HANDLE ADDS NO CONTENT. Same claim, matched length; the only
       difference between a and b is a named mechanism. Otherwise the arm
       tests informativeness.
    2  FRESH SESSION PER TRIAL. No carryover; engagement in trial n must
       not be licensed by trial n-1.
    3  THE CODER IS BLIND TO CONDITION. The handle is redacted from the
       stimulus before coding. Mechanical, enforceable, and it removes the
       only place the hypothesis could leak in.
    4  THE AUTHOR IS NOT THE CODER.
    5  NO PASS STATE. The arm reports engagement rates per condition. There
       is no output that reads "H3b confirmed."

## What it would show

    engagement higher in b than a      -> consistent with H3b. The handle
                                         is a precondition for engagement,
                                         not a terminus for inquiry.
    no difference                      -> H3b not supported on this
                                         stimulus set. Report it.
    engagement higher in a             -> H3b falsified in the direction
                                         nobody predicted. Report it
                                         louder.

**H3 and H3b separate here.** Under H3, a term arrives and inquiry stops.
Under H3b, without a term inquiry never starts. The two make opposite
predictions about what follows the handle, and only one of them is testable
by counting tokens.

## The existing positive case — and why the arm does not lean on it

> Shadow Hunting is an existing positive case — a wrapper with a method that
> kept developing underneath is exactly the H3b signature.

**The signature reading requires the separation claim**, which is currently
`RECORDED, NOT ADOPTED` (`GUESSED.md` #22): *wrapper* and *method that kept
developing underneath* presupposes the two decompose, and one word with two
authors and no per-invocation marker is entangled by default.

**So the case cannot do evidential work for H3b while the separation is
unadopted, and the dependency runs the other way:**

    this arm, run prospectively   ->  supports H3b independently
    H3b supported                 ->  supports reading Shadow Hunting as
                                      an H3b case
    that reading                  ->  supports the separation

The arm is **upstream of all three.** That is a reason to run it rather than
a criticism of the case — and it is why the design above uses fresh stimuli
and not the repo.
